# ことのは収集IME v0.16（Android MVP）

自分の日本語入力データを、端末内で安全に蓄積するためのAndroid IME試作です。

## 現在できること

- Androidの正式な `InputMethodService` として動作
- Gboardの現行12キー配置を参考にした、クリーンルーム実装の日本語フリック入力
- 中央3列のかなと左右の操作列からなる5×4配置、3dp基準の角丸を使ったシャープな表示
- 絵文字とクリップボードだけに絞った、余白のある最小ツールバー
- キーボード操作アイコンはGoogle公式Material Icons Roundを使用（Apache License 2.0）
- フリック中は72dpの円形バブルをキー上端から18dp離して表示し、選択文字を大きく表示
- Android標準の長押し時間後に5方向ガイドへ切り替え、指の移動に選択文字が追従
- 濁点・半濁点・小文字、句読点フリック
- 12キー最下段はGboardの「言語切り替えキーを表示」OFFと同じ、`濁点・小文字 / わ / 句読点・！？`配置
- IME切り替えはAndroid下部ナビゲーション領域のシステムボタンを使用（OSにより地球儀またはキーボード形）
- 左右カーソルキーのタップと上下左右4方向フリック、スペースキーの横スワイプ移動
- 削除キーの左スワイプによる直前語の一括削除と、長押し時間360ms・最大約37回/秒まで加速する連続削除
- 未確定かな・変換候補・確定文字で一貫した削除。結合文字、国旗、肌色、ZWJ絵文字も見た目の1文字単位で削除
- かな12キーの `あa1` から半角英字QWERTYへ切り替え
- 半角英字面は独立した数字段を上に置いた5段QWERTY。下段は `あa / ?123 / , / 日本語 / . / ← / → / Enter`
- Shiftは1回で次の1文字を大文字、素早い2回タップでCaps Lock。英字の長押し記号、半角空白、空白キーの横スワイプ移動にも対応
- `?123` で基本記号QWERTY、`=\<` で追加記号QWERTYへ切り替え。`ABC` で英字、`あa` でかな12キーへ戻る
- セッション内クリップボード（外部からコピーした内容は学習ログへ保存しない）
- Unicode Emoji 17.0のカテゴリ別絵文字パネルと最近使った絵文字
- 公式OSS MozcのAndroidライブラリとOSS辞書による、完全オフラインの予測・かな漢字変換
- 候補バーと、最大80候補を3列で縦スクロールできる全候補一覧
- 変換中は選択候補を入力欄にも表示し、変換キーの連打で次候補へ移動
- 未確定文字はダーク／ライトテーマ別の背景色と下線で明確に表示
- かな12キーの空白は全角、半角英数QWERTYの空白は半角で入力
- 変換候補を選択中に次の文字を打つと、現在の候補を自動確定して新しい読みを開始
- 候補選択をMozcへ返す端末内ユーザー履歴学習（Mozcプロファイルも端末内だけに保存）
- Mozcを読み込めない場合だけ小規模フォールバック辞書へ自動切り替え
- 変換候補、選択順位、読み、確定、未確定編集、削除、訂正系列をイベントとして記録
- 候補の出所と確定方法、カーソル位置、Mozc／アプリ／配列バージョンを保存
- かなフリックの基準キー、方向、移動量、所要時間、開始位置、長押しガイド表示を保存
- 前後文脈の記録は任意（初期値OFF、最大64文字）
- パスワード、PIN、学習禁止欄では自動的に記録停止
- アプリ名は短いハッシュIDとして保存
- Android KeystoreのAES-GCM鍵でイベント本文を暗号化
- 入力スレッドとは別のワーカースレッドでSQLiteへ保存
- JSONLエクスポートと全削除
- 内蔵IMEテストパッド
- `INTERNET` 権限なし

## Kotlin移行

v0.13で `dev.kotonoha.collector` 配下の手書き実装とテストをKotlin 2.0.21・JVM 17へ全面移行しました。IMEサービス、フリックView、設定／テスト画面、Mozcセッション制御、暗号化保存を含めてKotlinです。Javaで残しているのは、上流互換を保つためのMozc JNIブリッジ1ファイルと生成済みProtocol Buffers 5ファイルだけです。

v0.14では、候補を確定して別の読みを続けた際にMozcの古い未確定状態が残る経路を修正しました。最初の変換要求では現在の読みを必ずネイティブセッションへ再送し、候補確定後はコンテキストをリセットしてからセッションを破棄します。また「つ」の濁点／小文字キーは、一般的な12キー配列に合わせて `つ → っ → づ → つ` の順に変更しました。

v0.15では収集形式をschema v3へ拡張しました。未確定文字の挿入・削除・濁点／小文字化を `COMPOSITION_EDIT` として記録し、`composition_id` で同じ入力を、`correction_id` で削除と後続の置換入力を連結します。候補の出所、確定方法、カーソル位置、バージョン情報、かなフリックの方向・移動量・所要時間も保存します。既存のschema v2イベントは書き換えず、新規イベントだけがv3になります。

v0.16では、かな入力中の `、。？！…「」（）〜` を即時確定せず、通常のかなと同じ未確定文字列へ追加するように変更しました。句読点を含む全文字列は同じ `composition_id` のまま維持され、Enterまたは明示的な確定操作まで入力欄へコミットされません。

## Mozcについて

Mozc公式リポジトリのコミット `851c3fe33060d2a6090363e4d7ec44fafde2c03d` から、Android向け `libmozc.so` を `arm64-v8a` / `x86_64` の2 ABIでビルドし、公式OSS用 `mozc.data` とともに同梱しています。JNIではMozcのProtocol Buffersコマンドを使い、予測、明示変換、候補選択、セッション管理を行います。ネットワーク接続は不要です。

OSS版Mozcは公式にも無保証で、辞書はGoogle日本語入力で使われるものとは異なります。そのため、GboardやGoogle日本語入力と候補や順位が完全一致するものではありません。また、公式Android APKクライアントは廃止済みなので、現代Android向けUIとIMEサービスはこのプロジェクト側で実装しています。Gboardのソース・アセット・内部データは使用していません。

## ビルド

Android Studioでこのディレクトリを開き、SDK 34を指定して `app` をビルドしてください。コマンドラインでは次を実行します。

```bash
./gradlew assembleDebug
```

生成物は `app/build/outputs/apk/debug/app-debug.apk` です。

Mozcのネイティブライブラリ、辞書データ、生成済みProtocol Buffers Javaソースはリポジトリ内に同梱しているため、通常のAPKビルド時にMozcを再ビルドする必要はありません。Mozc自体を再生成する場合は、公式手順どおりMozcリポジトリで依存関係を取得し、BazeliskでAndroidパッケージをビルドしてください。

```bash
python3 build_tools/update_deps.py
bazelisk build package --config oss_android --config release_build
```

## 端末での使い方

1. APKをインストールして「ことのは収集IME」を開く
2. 「Android設定でIMEを有効化」を押してIMEを許可
3. 「使用するIMEを選択」から「ことのは収集IME」を選ぶ
4. 「テストパッドで入力を試す」でフリック・クリップボード・絵文字を確認する
5. 「入力イベントを収集する」を明示的にONにする
6. 必要な場合のみ「前後の文脈も保存する」をONにする
7. 保存データ画面からJSONLを書き出す

## クリップボードと絵文字

キーボード上端のクリップボードアイコンでクリップボード、上端または左側列の顔アイコンで絵文字を開きます。クリップボード履歴はIMEプロセスのメモリ内だけに最大12件保持し、アプリ終了後や端末再起動後には残りません。貼り付けた内容は入力学習用イベントにも記録しません。

絵文字一覧はUnicode Consortium公開の `emoji-test.txt`（Emoji 17.0）をアプリ内で解析しています。完全修飾された絵文字をカテゴリ別に表示し、描画時は画面内の行だけを処理します。

## Mozc候補

かな入力中はMozcの予測候補を上端の候補バーに表示します。右側の下向き矢印を押すと、最大80件の候補を3列の一覧で確認できます。スペース／変換キーを押すと明示変換になり、現在選択中の候補を青色で表示します。バーまたは一覧の候補を押すと入力欄へ確定し、その候補IDをMozcへ返して端末内学習へ反映します。

## JSONLイベント

各行は1イベントです。v0.15以降に記録する行は `schema_version: 3` です。主なフィールドは以下です。

- `type`: `CONVERSION_COMMIT`, `READING_COMMIT`, `DELETE_COMMITTED` など
- `input_mode`: `KANA_FLICK`, `LATIN_QWERTY`, `SYMBOL_QWERTY`
- `raw_input`: 入力ローマ字
- `reading`: ひらがな読み
- `committed_text`: 確定文字。削除イベントでは空文字
- `deleted_text`: 未確定または確定済みの削除文字
- `candidates`: 表示候補
- `selected_index`: 選択順位
- `candidate_source`: `PREDICTION`, `CONVERSION`, `NONE`
- `commit_method`: 候補タップ、次入力による自動確定、Enter、句読点など
- `composition_id`: 同じ未確定入力系列を結ぶID
- `correction_id`: 削除と後続の置換入力・確定を結ぶID
- `edit_operation`, `raw_before`, `raw_after`: 挿入・削除・修飾の差分
- `cursor_before`, `cursor_after`: 操作前後のカーソル位置。取得非対応欄では `-1`
- `gesture_*`: かなフリックの基準キー、方向、dp移動量、時間、キー内開始位置、長押し状態
- `engine_version`, `app_version`, `layout_version`: 学習データ生成環境
- `context_before`, `context_after`: 設定時のみ保存される文脈
- `app_id`: パッケージ名そのものではない短いハッシュID
- `session_id`, `sequence`: 入力欄ごとの順序を復元するための識別子

## プライバシー設計

収集は初期状態でOFFです。暗号鍵はAndroid Keystoreから取り出せず、DB内のイベント本文はAES-GCMで暗号化されます。明文になるのはユーザーがAndroidの保存先選択画面から明示的にJSONLを書き出したときだけです。Mozcのユーザー履歴とプロファイルもアプリ専用領域にだけ保存します。アプリはバックアップ対象外で、ネットワーク権限も要求しません。
